# Browser verification plan\n\nThis is the executable test specification for the next environment with Playwright or an equivalent real browser. Results must be recorded as PASS or NOT TESTED; HTTP 200 alone is not a runtime pass.\n\n## RH Manager Pro\n\n1. Open the portfolio and activate the RH Manager Pro Project Lab.\n2. Confirm the iframe leaves its loading state and the application is visible.\n3. Use the documented demo entry/login, open employees, create or edit a fictional employee, save, and verify the visible row/state changes.\n4. Open leave requests, submit a fictional request, approve or reject it, and verify the status.\n5. Navigate to reports/dashboard and confirm the state is reflected.\n6. Expand “How did this work?”, activate the repository link, and confirm it opens rh-manager-demo.\n7. Record console errors, failed network requests, iframe load failures, keyboard focus issues, and mobile layout issues.\n\n## GEMA Entreprise\n\n1. Open the GEMA Project Lab from the portfolio.\n2. Confirm the iframe loads without relaxing sandbox permissions beyond forms, scripts, same-origin, modals, and popups.\n3. Authenticate with the published demo account (admin@gema.dz / demo123).\n4. Create or edit a fictional equipment item or collaborator, then perform an assignment workflow.\n5. Verify the dashboard/list/detail state changes and persistence after refresh.\n6. Expand the architecture handoff and open the gema-entreprise repository.\n7. Record console errors, failed network requests, iframe load failures, keyboard focus issues, and mobile layout issues.\n\n## Portfolio shell\n\n1. Load the portfolio on desktop, tablet, and mobile viewport sizes.\n2. Confirm labs are lazy-loaded only after activation, with a visible loading state and a direct-demo fallback link.\n3. Tab through navigation, lab controls, details, iframe, and source links; verify visible focus and no keyboard trap.\n4. Trigger an iframe error/blocking case and verify the UI explains the limitation and exposes the direct demo link.\n5. Capture console errors and failed requests; verify screenshot alt text and heading order.\n\nNo browser automation was available during this hardening pass, so these runtime flows remain NOT TESTED until executed in a browser-capable environment.\n
